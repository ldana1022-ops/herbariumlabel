# نظام المستخدمين والصلاحيات والإشعارات وسجل النشاطات

إضافة طبقة كاملة للحسابات والصلاحيات فوق النظام الحالي، دون حذف أو تعديل أي عينة أو حقل موجود. جدول العينات يبقى كما هو (يُضاف إليه حقلَي مستوى الظهور فقط)، وكل صفحات العينات والليبل والباركود والاستيراد تبقى تعمل كما هي.

ملاحظة واحدة قبل البدء: أحتاج البريد الإلكتروني الذي سيكون حساب Super Admin (سأثبّته في قاعدة البيانات ليأخذ الصلاحية الكاملة تلقائيًا عند أول تسجيل دخول به).

## المراحل

### 1. الدخول والحماية
- صفحة `/auth`: تسجيل دخول، إنشاء حساب (مفتوح كما طلبت)، «نسيت كلمة المرور».
- صفحة `/reset-password` لتعيين كلمة مرور جديدة.
- كل صفحات النظام تنتقل تحت حماية تسجيل الدخول: لوحة التحكم، قاعدة البيانات، إضافة/تعديل عينة، الاستيراد، الطباعة.
- يبقى عامًا فقط: صفحة مسح الباركود `/s/الرقم` بعرض مختصر (الرقم التسلسلي، الاسم العلمي، العائلة، الموقع، الحالة) لعينات مستوى ظهورها Everyone؛ وزر «فتح السجل الكامل» يطلب الدخول.
- الرأس يعرض اسم المستخدم مع «تسجيل خروج» وأيقونة الإشعارات بدل الوضع المفتوح الحالي.

### 2. المستخدمون والصلاحيات
- كل مستخدم جديد يبدأ بصلاحية «عرض كل البيانات» فقط.
- صفحة `/admin/users` (Super Admin فقط): جدول بالاسم، البريد، الدور، الحالة، الصلاحيات، آخر دخول، تاريخ الإنشاء، وإجراءات (عرض، تعديل، الصلاحيات، تعطيل/تفعيل، حذف، إعادة تعيين كلمة المرور).
- محرّر صلاحيات لكل مستخدم، كل صلاحية مفتاح مستقل:
  - نطاق البيانات: كل البيانات / بيانات محددة / بياناته فقط / المدير فقط.
  - الإجراءات: إضافة، تعديل، حذف، استيراد Excel، تصدير Excel، تعديل العينات، تعديل الليبل، تغيير حالة العينة، إرسال طلبات، استقبال طلبات.
- المستخدم المعطّل يُمنع من الدخول ومن أي قراءة أو كتابة.
- لا يمكن لأي مستخدم تعديل صلاحيات Super Admin أو حذفه أو تعطيله.

### 3. مستوى ظهور العينات
- لكل عينة مستوى ظهور: Everyone / Admin Only / Selected Users، قابل للتغيير في أي وقت من صفحة العينة وبشكل جماعي من الجدول.
- كل العينات الحالية تُضبط على Everyone حتى لا يتغير أي شيء لديك اليوم.
- عند اختيار Selected Users يُحدَّد المستخدمون المسموح لهم.

### 4. الإشعارات
- مركز إشعارات بأيقونة 🔔 وعدّاد غير المقروء، مع «تحديد كمقروء»، «تحديد الكل»، وصفحة «كل الإشعارات».
- إشعار عند: تسجيل دخول، مستخدم جديد، إضافة/تعديل/حذف بيانات، استيراد، تصدير، تعديل عينة، تعديل ليبل، تغيير حالة، طلب جديد، قبول/رفض طلب، تغيير صلاحيات.
- نص الإشعار: المستخدم + العملية + السجل + التاريخ والوقت، مثال: «Sara updated sample NCVCH000012 — 18/08/2026 12:10 PM».
- Super Admin يرى كل إشعارات النظام؛ المستخدم يرى ما يتعلق به فقط.

### 5. سجل النشاطات
- صفحة `/admin/activity` لـ Super Admin: المستخدم، العملية، السجل، القيمة السابقة، القيمة الجديدة، التاريخ، الوقت، الجلسة/الـIP إن توفر.
- السجل للقراءة فقط — لا حذف ولا تعديل لأي مستخدم، بما في ذلك Super Admin.
- بحث وتصفية حسب المستخدم، التاريخ، العملية، العينة، الحالة.

### 6. الطلبات
- `/requests`: إنشاء طلب (مستخدم + عينة + نوع الطلب + تاريخ استحقاق اختياري)، يظهر للمستلم في مركز الإشعارات.
- حالات: Pending / In Progress / Completed / Rejected؛ المستلم يحدّثها حسب صلاحيته، وSuper Admin يرى كل الطلبات.

### 7. لوحات التحكم
- لوحة Super Admin: إجمالي المستخدمين، النشطون، المعطّلون، المتصلون حاليًا، آخر تسجيلات دخول، الطلبات المعلّقة والمكتملة، آخر النشاطات، آخر تغييرات البيانات، الإشعارات غير المقروءة، مع بحث وتصفية.
- لوحة المستخدم العادي: نفس لوحة العينات الحالية، مع إخفاء ما لا يملك صلاحيته، وإحصاءات محسوبة من العينات التي يحق له رؤيتها فقط.

### 8. التحديث الفوري
- الجداول والإشعارات تتحدث تلقائيًا عند أي إضافة/تعديل/حذف بدون تحديث الصفحة يدويًا.

## التفاصيل التقنية

- جداول جديدة: `user_permissions` (نطاق البيانات + مفاتيح الإجراءات + `is_active`)، `notifications`، `activity_log`، `requests`، `specimen_access` (المستخدمون المصرح لهم لكل عينة)، وحقول جديدة على `herbarium_specimens`: `visibility` (enum بقيمة افتراضية `everyone`) و`created_by` (nullable، يبقى فارغًا للعينات الحالية). لا تعديل على أي حقل قائم. `profiles` و`user_roles` القائمان يُستخدمان كما هما مع إضافة `super_admin` للأدوار و`last_login_at`/`is_active` إلى `profiles`.
- الصلاحيات تُفرض في قاعدة البيانات عبر RLS مع دوال `SECURITY DEFINER` في مخطط `private` (نفس النمط المستخدم حاليًا): `is_super_admin`، `has_action_permission`، `can_view_specimen`. سياسات العينات تُعاد كتابتها لتصبح: القراءة حسب مستوى الظهور ونطاق بيانات المستخدم، والكتابة/الحذف مشروطة بصلاحية الإجراء. الوصول العام (anon) يُقتصر على قراءة أعمدة محدودة لعينات Everyone عبر عرض (view) مخصص لصفحة الباركود.
- الكتابة الحساسة (إدارة المستخدمين، إعادة تعيين كلمات المرور، التفعيل/التعطيل، منح الصلاحيات) تمر عبر `createServerFn` مع `requireSupabaseAuth` وتحقق من الدور داخل الخادم قبل استخدام الوصول الإداري.
- الإشعارات وسجل النشاطات تُكتب عبر Triggers على قاعدة البيانات (insert/update/delete على العينات وتغيّر الصلاحيات والطلبات) حتى لا يمكن تجاوزها من الواجهة، مع تسجيل القيم السابقة/الجديدة للحقول المتغيّرة فقط. تسجيل الدخول يُسجَّل من الخادم عند نجاح الجلسة.
- التحديث الفوري عبر Supabase Realtime على `notifications` و`requests` و`herbarium_specimens` مع إبطال استعلامات TanStack Query.
- الترحيلات إضافية بالكامل (ADD COLUMN / CREATE TABLE) وتشمل GRANTs لكل جدول جديد؛ لا حذف بيانات ولا إعادة تسمية.
- تسجيل الدخول بالبريد وكلمة المرور، وإتاحة Google اختياريًا لاحقًا.
